# 山・山域をすすめるときの指針(Claude Code・Codex 共通)

「今週末、家族で行ける山は?」「デートに向いた山域は?」のように、同行者・目的に合わせて山をすすめるときの進め方。
同行者・目的(家族連れ・子供・デート・初心者・写真・健脚)が不明なら、聞き取るか、質問文からくみ取る。

1. **根拠は探索モードの数値**。スコア・稜線風速・体感温度・危険信号・降水量・`access`(登山/ロープウェイ/ゴンドラ/バス 等)を
   表にして示す。数値は実行結果から取り、推測で埋めない。実行が古いときは取り直す(`--out` で保存して必要な日・山だけ読む)。
2. **目的に合う絞り込み**
   - 子供連れ・初心者・デート: `access` が乗り物で標高を稼げる山を優先する。危険信号が出ている山、体感が氷点下の山、3000m級は避ける。
   - 健脚・写真: スコアと稜線の天気、見通し(視程・雲量)を優先する。
3. **日程の比較**。土日を並べ、下がる日はその理由(雨天割合の上昇など)を数値で示す。
   - **76座に無い山をすすめるとき**: 有名な山はWeb検索で選び(出典を示す)、天気は診断モードの `--name/--lat/--lon/--elevation` で出す。座標・標高は検索で調べた値を使い、出典と「登録外・地形データなし」を明記する。比較は日別スコア・危険信号の同じ指標で行う。
4. **一般知識は区別する**。所要時間・難易度・混雑・駅やバスからの行きやすさはデータに無いので「一般知識」と明記する。
   運行状況・駐車場・時刻は各自で確認するよう添える(データから確認した値のように書かない)。
5. **予報の限界を添える**。MSM範囲(約3日)より先は ECMWF のみの粗い見積もり。前日にもう一度実行して確認するよう促す。
6. **同行者への配慮を添える**。子供連れ・初心者には、防寒(体感が低いとき)と、午前に下山できる計画(スコアは午前の稜線が基準)を添える。
7. 希望があれば、絞り込んだ山の HTML レポートを作る(`report_style.md` の手順)。HTML で出すときは、次を守る。
   - **おすすめの山は表にする**。探索の `commentary` に `"picks": ["山名", ...]`(おすすめ)と `"avoid": ["山名", ...]`(避ける山)を入れ、`"dates"` で対象日を絞る。
     日ごとのスコア・危険信号・風・体感・雨天割合・降水の表が、先頭(総評の次)に自動で入る(数値を手で写さない)。`picks` があると、日別タブの要約から「上位: …」が外れ、おすすめと食い違わない。
   - **避ける山も理由つきで見せる**(`avoid`)。スコアが高くても外した山(強風警戒・体感が氷点下・3000m級など)は、数字を表に出して、総評で外した理由を書く。
   - **確信度は、おすすめの全候補で確かめてから書く**。探索モードには確信度が無いので、候補ごとに診断モード(`mountain_weather_detail.py --mountain <山> --out ... --json-out ...`)を実行し、対象日の確信度を総評・注意に書く(確信度が低い日は「予報が大きく動きうる」と添える)。
   - **体力面(歩行時間・標高差・難易度)はデータに無い**。「乗り物で標高を稼げる」ことを目安にしたと明記し、それ以外は「一般知識」と書き分ける。所要時間・運行状況は各自で確認するよう添える。
   - **目的に合わせて日を選ぶ**。対象日の全山のスコアが低い日(例: 全山0点)は、その日は避けると明言し、歩ける日を示す。
