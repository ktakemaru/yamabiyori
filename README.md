**「その日、その山の稜線は、濡れずに歩けるか」** を数字で答える、登山特化型の天気予報ツール。

Open-Meteoの無料APIだけで動き、気象庁MSM(5km格子・3日先まで)とECMWF IFS(全球・14日先まで)を自動マージ。地上の天気ではなく**山頂標高の空気**を見て、雲量・視程・降水を1本の「登山向け総合スコア」にまとめ、雷・強風・低体温症は別枠の「危険信号」として警告する。関東甲信・北陸信越・東北南部・伊豆の**76座**に対応。

> 一般の天気予報が「甲府市は晴れ」と言う日でも、北岳の稜線は湿った南西風でガスに巻かれていることがある。ヤマビヨリはその差を、気圧面データと山岳気象の基本則(逆転層の蓋・強制上昇・地形の風上風下)で読む。

> **v1.6.0 (2026-09-23) で、1〜2日目の雲量の補正を見直しました。** 直近1〜2日に使う気象庁MSMの山頂雲量は、
> 補正に使う較正表を作ったときと本体とで計算方法(使う気圧面の数)が違っていて、晴れる確率を低めに見積もっていました。
> これを揃えたため、**1〜2日目のスコアが山によって数点変わることがあります**(検証では平均+1点、5点以上動くのは約1割。
> 日ごとの上位の顔ぶれはほぼ変わりません)。3日目以降のスコアは変わりません。**「行ける」の目安 70点は v1.5.0 から変わっていません。**
> v1.5.0 (2026-09-19) では、雲量の数字をそのまま信じず過去の的中率にもとづく「晴れる確率」に直してから採点するようにし、
> スコアが以前より5〜20点ほど低く出るようになったため、目安を80点→70点に変えました。
> 詳細は [CHANGELOG](CHANGELOG.md) と [検証リポジトリ](https://github.com/ktakemaru/yamabiyori-backtest)。

## ヤマビヨリの特徴

**1. 山頂標高の値で判断する。**
気圧面(1000〜600hPa)の雲量・湿度・風・気温を、その時刻のジオポテンシャル高度で **1000m / 2000m / 3000m / 各山の山頂標高** へ線形補間する。「850hPa≒1500m」のような固定バンドではなく、燕岳なら2763m、富士山なら3776mの空気をそのまま評価する。

**2. 「濡れるか・ガスに巻かれるか」を山岳気象の基本則で判定する。**
Open-Meteoの降水確率は山では当たりにくい。そこでMSM範囲内は降水量に加えて次の3つの物理ルールで「雨天時間」を数える。

| ルール | 判定 | 背景 |
|---|---|---|
| 湿潤層 | 山頂〜600m下の層でRH≥90%かつ雲量≥40% | 稜線が雲の中=濡れる・ガス |
| 逆転層の蓋 | 山頂400m上が乾いていれば下の湿潤層は数えない | 雲海の日を0点にしない |
| 強制上昇 | 山頂風≥10m/sで、湿った下層(RH≥80%)を持ち上げた凝結高度が山頂以下なら湿潤扱い | 火打山・西穂高岳の実況ミスから導入(v1.3.0) |

**3. 危険信号はスコアに混ぜない。**
雷(CAPE)・稜線の強風・低体温症(風冷+濡れ補正の体感温度)は「平均すると薄まる」性質のものなので、スコアから切り離して**注意 / 警戒 / 危険**の3段階で別枠表示する。スコア100点でも「⚠雷警戒」が付く日がある。

**4. 一要素でも悪ければスコアは落ちる。**
雲量(稜線帯/午後)・視程・降水(活動時間中の雨天割合)を**重み付き幾何平均**で合成。晴れて視程が良くても午後に雨が来る日は高得点にならない。

**5. 活動時間は日の出・日没から決める。**
稜線帯滞在(日の出+1h〜12時)、活動時間(日の出−1h〜日没+30分)を毎日計算。9月と12月で2時間以上ズレる「固定8〜17時」方式を廃止した。

**6. 地形を読む(地理院DEM)。**
国土地理院の標高タイルから76座の山頂まわり16方位の地形を事前計算し、山頂風と稜線帯下端の風の2段で**風上(谷側)/風下(山越え)**と地形性上昇流を表示する(現在は表示のみ、スコア未反映)。

**7. 数値の裏を取る材料も一緒に出す。**
気象庁の実況天気図・予想天気図(+24h/+48h)、ひまわり赤外/雲頂強調画像、ECMWF 51メンバーのアンサンブル確信度、雲海チャンス、天候の変わり目時刻。診断モードではこれらを使って「気圧配置 → 実際の雲 → MSM数値」の順に概況を説明する。

**8. 自分で測って、直している。**
予報を実際の観測と1時間ごとに突き合わせるバックテスト基盤
([yamabiyori-backtest](https://github.com/ktakemaru/yamabiyori-backtest))を持ち、その結果を製品に反映している。
山頂雲量の検証は2026年6月12日〜9月17日の98回分の予報(MSM・ECMWF、00Z)を、麓のアメダス日照
(白馬・野辺山・奥日光の3地点で通して。安達太良山/鷲倉は9月11〜18日の8日分のみ)と、
富士山頂自身の日照(7月10日〜8月31日)に当てたもの。
「晴れ/曇りをどれだけ言い当てるか」(AUC、1.0が完璧・0.5が当てずっぽう)は
**1日前(MSM)で0.78、3日前(ECMWF)で0.77、7日前で0.61**。この検証から v1.4〜1.6 で3つを直した:
- **雲量の数字をそのまま信じない。** 予報の「雲量0%」が実際に晴れだったのは約7割、「5%」では約5割だった。
  そこで雲量%を過去の的中率で「晴れる確率」に直してから採点する。遠い日ほど的中率が下がるので、
  遠い日のスコアは自然に控えめになる。
- **MSMの山頂雲量の計算を較正表と揃えた。** 直近1〜2日に使うMSMでは、較正表を作ったデータと本体とで山頂雲量の計算に
  使う気圧面の数が違い(本体は900/800hPaも使う)、標高2,000m前後の山で晴れる確率を低めに見積もっていた。
  本体と同じ計算の山頂雲量で1〜2日目の較正表を作り直した(v1.6.0)。
- **「雨」の閾値を実測で見直した。** 従来の「1時間0.1mm以上=雨」は、実際に測れる雨(0.5mm以上)が
  降った時間の2.6〜4倍を「雨」と言っていた。閾値を引き上げ、霧雨レベルを雨扱いしなくなった。

スコア式の変更は従来どおり、参照日(唐松岳9/6=荒天・立山9/5=快晴・槍ヶ岳9/5)を固定して再計算し、
登山SNSの実況報告と1座1日ずつ突き合わせて確認する。他社予報サイトの答えを覗いて合わせることはしない。

**9. どこまで信じてよいかを明示する。**
検証で分かった限界はそのまま書く(「精度と限界」参照): 信用してよいのは**3日前まで**、
山頂雲量の較正は**6〜9月のデータのみ**、**夜間**と**稜線の風**は実況が無く未検証。スコアはこの範囲で読むこと。

### 探索モード — 「今週末、どこがいい?」

`mountain_weather_mvp.py`。76座を横断してスコア順に並べ、70点以上の山だけを今週・来週・2週間先の3期間で一覧する(非対話。v1.5.0 でスコア水準が下がったため目安を80→70に変更)。

### GPXルート診断 — 「この計画書のルートで、どの地点が危ないか?」

`mountain_weather_detail.py`(GPXモード)。ヤマレコの登山計画書GPXから登山口・山小屋・山頂などの地点を自動抽出し、**地点ごとの標高に補間した値**で天気を評価する。オプションで天気アイコン付きのルート地図PNGも生成できる。

## スコアの仕組み

```
登山向け総合スコア = 幾何平均( 雲量(稜線帯/PM) ^0.25 × 視程 ^0.25 × 降水(雨天割合) ^0.50 )
危険信号(スコア外)  = 雷(CAPE) / 稜線の強風(日中ピーク) / 低体温症(体感温度)  → 注意・警戒・危険
```

| 軸 | 何を見るか | 山頂標高の値? |
|---|---|---|
| 雲量 | 毎時の山頂雲量を実況晴れ率で較正した「実効雲量」(v1.5.0〜、遠い日ほど辛い。v1.6.0 から基準値は較正表の行ごとに持ち、MSMの1〜2日目は本体と同じ7面の山頂雲量で学習した行)の、稜線帯滞在時間の平均と午後(12時〜日没)の連続2時間平均の最大値の悪い方 | ○ |
| 視程 | 稜線帯滞在時間の平均(広域モデル値) | − |
| 降水 | 活動時間中の「雨天時間の割合」+ 活動時間内の合計降水量(20mmで満点ペナルティ) | ○(湿潤層・強制上昇) |
| 雷 | ECMWF CAPEの活動時間内ピーク | − |
| 強風 | 山頂風速の日中ピーク | ○ |
| 低体温症 | 山頂の気温 − 風冷 − 濡れ補正(−3℃) | ○ |

MSM範囲内(今日〜+2日)は上記の物理ルールで時間単位に判定し、それより先はECMWF降水確率の期待値でならす(4日目以降の時間別詳細は意図的に追わない)。式と定数はすべて `mountain_weather_core.py` に集約され、変更理由は [CHANGELOG.md](CHANGELOG.md) に日付つきで残している。

## データソース

| データ | 提供元 | 用途 |
|---|---|---|
| 気象庁MSM(`jma_msm`、5km格子、〜3日先) | Open-Meteo | 気圧面の雲量・RH・風・気温・降水量(近距離・高精度) |
| ECMWF IFS 0.25°(〜14日先) | Open-Meteo | 4日目以降の予報、降水確率、CAPE |
| ECMWF ENS(51メンバー) | Open-Meteo | アンサンブル確信度(診断モード) |
| 実況・予想天気図 | 気象庁 | 診断モードの概況説明(オプション、Playwright) |
| ひまわり赤外/雲頂強調画像 | 気象庁 | 「今まさに雲があるか」の裏取り(オプション、Pillow) |
| 標高タイル(DEM) | 国土地理院 | 地形レイヤー(風上/風下・地形性上昇流) |

すべて無料・APIキー不要。レスポンスは `cache/` に3時間TTLでキャッシュされ、76座の再計算は数秒で終わる。

## 精度と限界(正直なところ)

### バックテストで測ったこと(詳細は [yamabiyori-backtest](https://github.com/ktakemaru/yamabiyori-backtest))

山頂雲量の検証は、2026年6月12日〜9月17日のMSM・ECMWF予報98回分(00Z)を、
麓のアメダス日照(白馬・野辺山・奥日光の3地点で通して。安達太良山/鷲倉は9月11〜18日の8日分のみ)と、
富士山頂自身の日照(7月10日〜8月31日、774時間)に1時間ごとに当てたもの。
地上の全雲量については2025年9月18日〜2026年9月17日の1年分の予報を保存しており、
観測の揃う約5か月分(2026年1月15日〜2月28日、6月11日〜9月18日)で別途確認した。
寒候期(1〜2月の45日分)は暖候期より0.04〜0.06低い傾向が見えているが、標本が少なく(n=1,483)確定していない。

| 何日前の予報か | 担当モデル | 晴れ/曇りの言い当て(AUC) | 富士山頂の実況で見ると | 読み方 |
|---|---|---|---|---|
| 1日前 | MSM | 0.78 | 0.75 | よく当たる |
| 3日前 | ECMWF (MSMは0.71) | 0.77 | 0.76 | 信用してよい範囲 |
| 5日前 | ECMWF | 0.71 | 0.64 | 傾向として読む |
| 7日前 | ECMWF | 0.61 | 0.56 | ほぼ気候値。「その週は良さそう」程度 |
| 10日前 | ECMWF | 0.55 | 0.55 | 当てずっぽうと大差ない |

(AUCは1.0が完璧、0.5が当てずっぽう。左の列は麓の日照で測った値、右は富士山頂自身の日照で測った値で、
登山者が山頂で体験する精度は右に近い。)

- 直近3日はMSM(5km格子)、それより先はECMWF(25km格子)。**3日前までは山頂の値として信用してよく、
  7日先以降は雲量スコアの差にほとんど意味が無い。** 14日表示は「傾向」として読む。
- 雲量の数字は「順序」は正しいが「大きさ」は雲量%ではなかった(0%でも晴れは約7割)。v1.5.0 で
  過去の的中率にもとづく確率に直してから採点している。v1.6.0 で、MSM の1〜2日目の較正を本体と同じ
  山頂雲量の作り方(900/800hPa を含む補間)で学び直した。
- 降水「あり」の閾値は実測で見直した(v1.4.0)。それでも1時間単位の雨のタイミングは、当日でも空振り・見逃しが残る。

### 検証できていないこと
- **山頂雲量の較正は6〜9月の日中のデータで作っている。冬は、山頂に雲がかかる予報の日のスコアが低めに出る可能性がある。**
  冬(10〜5月)にも同じ表を使っていて、短いリード(1〜2日目相当)での暫定検証では、山頂に雲がかかる予報の時間
  (較正後の晴れ確率0.12以下)でも麓では13〜43%の時間が晴れていた。晴れ予報の日は影響を受けない。麓の日照で確かめているため、
  山頂だけ雲の中という冬型の日にどこまで当てはまるかは未確認。積雪期・残雪期は未対応。
- **冬の3日目以降の較正は未検証。** 冬の検証は短いリード(1〜2日目相当)についての暫定的なものだけで、冬の3日目以降について
  較正が良いか悪いかは確かめていない。次の冬(2026-27)のデータで再評価する。
- **MSMの3〜4日目は旧式の較正のまま。** 取得日から3〜4日目のMSMの時間(1回の予報あたり平均29時間)は、較正表の入力
  (山頂雲量の作り方)が本体と違う旧版のまま(900/800hPaを使わずに学習)。2027年3月に作り直す予定。
- **夜間**(夜明け前の雲海・星空)は実況が日照のため検証できていない。ひまわり画像での検証は未着手。
- **稜線の風**は実況が存在しない(富士山も2004年に風の観測を終了)。風の数値は他サービスとほぼ一致するが、精度の裏付けは無い。
- 3000m級の山頂そのものの実況は富士山1点(7月10日〜8月31日)。3000m級での較正の妥当性は暫定
  (槍ヶ岳9/5のように、実況は晴れなのに較正で66点まで下がる参照例がある)。
- 濡れ補正(−3℃固定)・視程閾値は未検証。

### 他サービス比較・登山記録との照合で分かっていること

他サービス(てんきとくらす・Windy・SCW・Mountain-Forecast・WeatherNews)との比較と、登山SNSの実況報告との突き合わせから。

**一致しているところ**
- 標高を揃えて比べると、雲量・気温・風速は他サービスとほぼ一致する(山頂気温は1℃前後、山頂風速は0.5m/s程度の差)。
- 2026-09-12の実況照合(11座・11日分)では、**8座がタイミング・性質とも一致**、1座が軽微な立ち上がり遅れ、2座が大きなミスマッチだった(照合前に大きく外れていた火打山9/6・西穂高岳9/10は強制上昇ルールで改善)。
- 雲海(地上は曇り・稜線は快晴)の構造検出は複数回、実況で裏付けられている。

**まだ弱いところ**
- 2〜3日先の**降水ピークがどの日か**の精度は他サービスと同程度で、モデル自体の不確実性が支配的。
- 稜線高度の飽和が終日続く予報が外れて正午に晴れ間が出るケース(谷川岳9/10型)は、同じ入力からは直せない。衛星画像との同時刻突き合わせが次の候補。
- 雲量軸は「山頂の空気の飽和度(ガスの代理指標)」であって「空がどれだけ雲に覆われるか」ではない(Open-Meteoの気圧面雲量はRHからの近似値)。展望の予想には地上の全雲量の方が適切。
- 槍ヶ岳のような狭い岩峰のガスは、5km格子より小さい現象なので拾えない。
- **積雪期・残雪期は未対応**(無雪期の登山を前提に設計)。
- 濡れ補正(−3℃固定)や視程閾値は未検証。

検証の記録は `skills/yamabiyori/SKILL.md` の「未検証・今後の課題」と「既知の精度傾向」に1座ずつ、
バックテストの結果は [yamabiyori-backtest](https://github.com/ktakemaru/yamabiyori-backtest) の `docs/` に残している。

## Codexで試す

プログラミングに慣れていなくても、自分のPCの Codex(OpenAI のコーディングエージェント。CLI・IDE拡張・デスクトップアプリ)に
頼めばセットアップから実行・小さな改造まで進められるようにしてある(ChatGPT の無料枠でも試せるよう、
Codex が読む量と試行回数を少なくする構成にしている)。Codex への指示は [AGENTS.md](AGENTS.md) にまとめてある。

1. **Python を入れる(3.10以上)。** Windows は [python.org](https://www.python.org/downloads/) のインストーラーで、最初の画面の
   「Add python.exe to PATH」にチェックを入れる(入れ忘れると `python` と打ったときに Microsoft Store が開く)。
   macOS も python.org のインストーラーでよい。
2. **このリポジトリを手元に置く。** Git があれば `git clone https://github.com/ktakemaru/yamabiyori.git`。
   Git が無ければ GitHub のページの「Code」→「Download ZIP」で落として展開する。
3. **Codex でそのフォルダを開く**(CLI ならフォルダに移動して `codex` を起動)。
4. **次のように頼む。** そのままコピーして使える:

```text
このリポジトリを理解して、セットアップして実行してください。
AGENTS.md の手順に従い、最初は軽量実行(--limit 3)で動作確認してください。
```

うまく動いたら、たとえば次のような改造も頼める:

```text
探索モードを、東京から近い山だけで実行できるようにしてください。
スコアの計算には触れず、山の選び方だけを変えてください。
```

途中でネットワーク(pip や天気データの取得)の許可を求められたら、許可する。
天気データの取得に失敗したときは、たいてい Open-Meteo 側の一時的な問題なので、時間をおいてやり直す。

## セットアップ

以下は Windows PowerShell 表記。macOS/Linux では `./venv/Scripts/python.exe` を `./venv/bin/python`、
最初の `python` を `python3` に読み替える。

```powershell
python -m venv venv
./venv/Scripts/python.exe -m pip install -r requirements.txt
./venv/Scripts/python.exe -X utf8 scripts/check_setup.py     # セットアップ確認([NG] があれば案内に従う)
```

**実行するときは `-X utf8` を付ける。** Windows の Python 3.14 以前では、付けずに出力をパイプで受けると
`⚠` などの記号で `UnicodeEncodeError` になることがある(本体のスクリプトは付け忘れても UTF-8 で出力するようにしてある)。
Windows PowerShell 5.1 で `>` を使うと文字化けするので、出力をファイルに残すときは `--out ファイル名` を使う。

必須の依存は `requests` と `numpy`(地形レイヤー)のみ。以下のオプション機能を使う場合は `requirements.txt` のコメントに従って追加インストールする。

| 機能 | 追加パッケージ |
|---|---|
| 気象庁天気図の取得(診断モードの概況説明) | `playwright` + `playwright install chromium` |
| ルート天気マップPNG、ひまわり画像 | `Pillow` |

## 使い方

```powershell
# 探索モード: 全山ランキング(非対話。初回は数分かかる)
./venv/Scripts/python.exe -X utf8 mountain_weather_mvp.py
./venv/Scripts/python.exe -X utf8 mountain_weather_mvp.py --limit 3        # 動作確認用: 先頭3座だけ
./venv/Scripts/python.exe -X utf8 mountain_weather_mvp.py --region 伊豆     # 地域で絞る(複数回指定可)
./venv/Scripts/python.exe -X utf8 mountain_weather_mvp.py --out out/ranking.txt  # 結果をUTF-8でファイルに保存(out/ はgitignore済み)

# 診断モード: 対話的に山を選択(1=山選択 / 2=GPXルート診断)
./venv/Scripts/python.exe -X utf8 mountain_weather_detail.py

# 診断モード: 非対話(番号はリスト順なので --list で確認。山名の一部でも可)
./venv/Scripts/python.exe -X utf8 mountain_weather_detail.py --list
./venv/Scripts/python.exe -X utf8 mountain_weather_detail.py --mountain 富士山

# テスト(オフライン)
./venv/Scripts/python.exe -X utf8 -m unittest
```

探索モードの主な調整パラメータ(`mountain_weather_mvp.py` 冒頭): `REGION_FILTER`(空=全地域)、`TOP_N_PER_DAY`、`MIN_SCORE_THRESHOLD`(既定70点。v1.5.0で80から変更)。

## Claude Codeとの連携

このリポジトリはClaude Codeプラグインとして構成されている(`.claude-plugin/plugin.json`)。インストールすると `skills/yamabiyori/SKILL.md` が読み込まれ、「富士山の天気は?」「今週末どこかいい山ない?」「このGPXのルートを診断して」のような質問に、Claude Codeがこのツールを実行して答える。診断モードでは天気図・衛星画像を読んだ概況説明つきで、探索モードではランキングをHTMLの一覧にまとめて返す使い方を想定している。

```bash
# このリポジトリをプライベートマーケットプレイスとして追加してインストール
claude plugin marketplace add https://github.com/ktakemaru/yamabiyori
/plugin install yamabiyori@yamabiyori-marketplace

# ローカルで動作確認だけしたい場合(マーケットプレイス登録不要)
claude --plugin-dir .
```

## ファイル構成

| パス | 役割 |
|---|---|
| `mountain_weather_core.py` | 共有基盤。山リスト(76座)、気圧面→標高補間、湿潤層/強制上昇ルール、スコア式、Open-Meteoキャッシュ、ひまわり画像取得。単体では実行しない |
| `mountain_weather_mvp.py` | 探索モード本体 |
| `mountain_weather_detail.py` | 診断モード(山選択・GPXルート診断)本体。天気図取得・ルート地図PNG・アンサンブル確信度もここ |
| `mountain_terrain.py` / `precompute_terrain.py` / `terrain_profiles.json` | 地形レイヤー。地理院DEMから76座分を事前計算済み(`terrain_cache/` はタイルキャッシュ、自動生成) |
| `cli_output.py` | `--out`(出力を UTF-8 BOM付きでファイルに保存)の共通処理 |
| `tests/`, `scripts/check_setup.py` | オフラインのテスト(参照3日の回帰チェックは `tests/fixtures/refs/` のフィクスチャで動く)とセットアップ確認 |
| `AGENTS.md` | Codex などのコーディングエージェント向けの指示(セットアップ・成功条件・変更してよい範囲) |
| `scratch_past_date.py` / `scratch_validate_refs.py` | 検証ツール。過去日付の再計算(実況照合用)と、参照3日の回帰チェック |
| `skills/yamabiyori/SKILL.md` | 設計ドキュメント本体。スコア式の根拠、各機能の設計判断、既知の落とし穴、検証記録 |
| `skills/yamabiyori/references/weather_map_reading.md` | 天気図読解の手引き(概況説明用) |
| `.claude-plugin/plugin.json`, `marketplace.json` | Claude Codeプラグインのマニフェストとプライベートマーケットプレイス定義 |
| `CHANGELOG.md` | 仕様・スコア式の変更履歴(日付・内容・理由) |
| `cache/`, `screenshots/`, `maps/` | 実行時に自動生成(Open-Meteoレスポンス、天気図・衛星画像、ルート地図PNG)。gitignore済み |
