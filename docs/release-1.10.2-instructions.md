## 4. 第 1 部: 地形の風向の選び方を決まった形にする

### 4.1 不具合

`mountain_terrain.py` の `max(set(dirs), key=dirs.count)`(活動時間の風向の多数派を選ぶ行)は、いちばん多い風向が 2 つ以上あると、**実行するたびに違う風向を選ぶことがある**(`set` の順が実行ごとに変わるため)。同じ予報なのに、ランキングの「地形」の列(`頂:並(西)` の括弧の中など)が変わる。スコアには入らない表示だけの値だが、同じ入力で表示が変わると混乱のもとになる。

### 4.2 直し方

- いちばん多い風向が 1 つなら、今までと同じ。
- 同数のときは、**その風向が最初に出た時刻が早いほう**を選ぶ(`dirs` の並びで、先に出たほう)。実行するたびに同じ結果になる。
- 同じ書き方(`max(set(...), key=...count)`)がほかの場所にもないか、リポジトリ全体を探す。あれば同じ直し方をし、場所を報告書に並べる(保護領域の中にあった場合は直さず、報告書に書く)。
- この関数の、ほかの値(風上・風下の時間数、上昇流の平均と最大、ラベル)は変えない。

### 4.3 確かめ(通信なし)

- テストを足す: 同数の風向の入力で、`PYTHONHASHSEED` を変えて何回実行しても同じ風向になる(テストの中から子プロセスを 3 つほどの種で起動する形、または `set` に頼らないことを直接確かめる形)。多数派が 1 つのときは、今までと同じ。
- 手元に保存済みの予報(`cache/`)が残っていれば、探索モードを通信なしで、種を 3 つ変えて実行し、変更前(main)と変更後で比べる。
  - 変更後: 3 回とも「地形」の列が同じ。
  - 変更前と変更後の違い: 「地形」の列の風向だけで、ほかの列・スコア・危険信号・`--json-out` の数値は 1 つも変わらない(山の ID で並べて比べる)。
  - 風向が同数になっていた山と日の数、表示が変わりうる山の名前を、報告書に並べる。
  - 保存済みの予報が無い・期限切れで通信なしでは動かないときは、この確かめを飛ばして報告書に書く(通信して取り直さない)。
- **既存のテストの期待値の例外**: 既存の見本・期待値に、同数の風向で選ばれた値が入っていて、新しい決まり(早いほう)と違うときだけ、その値を書き換えてよい。書き換える前に、その山と日の風向が本当に同数であることを確かめ、テストの名前・変えた値・同数だった風向を報告書に並べる。

`CHANGELOG.md` の `[Unreleased]` に 1 行書く。第 1 部だけで commit する。
