# 指示書: ヤマビヨリの 14 座の座標の修正(本体の変更。main に入れる PR の準備)

作成 2026-11-18 / 対象リポジトリ `C:/yamabiyori` / 無人で実行する。見込み 1〜2 時間。

## 0. 目的と背景
座標の点検(ブランチ `experiment/mountains-coordinate-audit`、報告書 `docs/mountains-coordinate-audit-report.md`)で、`MOUNTAINS` の座標が山頂から 300m 以上ずれている山が 14 座見つかった。唐松岳は白馬岳の近く(7.2km)、金峰山は北奥千丈岳の上(4.1km)にある。

**利用者の決定(2026-11-18)**: 300m 以上ずれている 14 座を直す(案 b)。直す値は、国土地理院「日本の主な山岳標高(1003 山)」の山頂の点。

**この指示書は、保護領域(`MOUNTAINS`)の変更についての利用者の承認である。ただし承認の範囲は、下の 3 章の 14 座の `lat`・`lon` だけ。** それ以外の保護領域の変更は承認していない。

今回やらないこと(決定済み):
- 300m 未満の山、1003 山に無い 11 座(石割山を含む)、浅間山(前掛山)、東天狗岳は直さない。
- 標高(`elevation_m`)は、どの山も変えない(立山・天城山も)。
- `id`・`name`・並び順を変えない。
- `msm_grid_elevation_m` の名前や値の意味は、調べて報告するだけ(6 章)。
- バージョン番号を上げない。

## 5. 修正と、直した後の確かめ
1. `MOUNTAINS` の 14 座の `lat`・`lon` を 3 章の値に直す。
2. テストを実行する。
   - 落ちたテストが「14 座の座標の値そのもの」を見ているだけなら、見本(`tests/fixtures/` など)を新しい値に合わせ、何を変えたかを報告書に書く。`id` の見本(`mountain_ids.json`)の id と name は変えない。
   - それ以外の理由で落ちたら、直さずに止める(T2)。
3. 足すテスト(通信しない): 14 座の座標が 3 章の値であること、id・name・`elevation_m`・座の数(76)が変わっていないこと。
4. **地形の見取りの作り直し**: 14 座について `precompute_terrain.py <山名>` を実行する(本体の決まりのとおり。国土地理院の標高タイルへの通信あり、1 枚ごとの間隔は本体のまま)。
   - 作り直しで変わるファイルを確かめ、14 座以外の山の値が変わっていないことを確かめる。変わっていたら、原因を調べて報告(直せなければ止める。T2)。
   - 14 座それぞれで、風上・風下などの見取りがどう変わったかを短く表にする。
5. **直した後の実通信**(4 章と同じ条件で、4 章の実行から時間をあけずに行う):
   - 探索モード全 76 座 → `C:/temp/coordfix/after.json`。診断モード 唐松岳・金峰山 → `after-m039.txt`・`after-m050.txt`。
   - 予報のキャッシュが効いて、直した山の値が古いままにならないことを確かめる(キャッシュの鍵が座標を含むか。含まないなら、14 座のぶんだけ取り直す方法を本体の決まりの中で探し、無ければ報告)。
6. **前後の比べ**(`before.json` と `after.json`):
   - 直していない 62 座: 判定・点数が同じであること。違う山があれば、予報の更新(モデルの新しい回)が間に入ったかを時刻で確かめ、入っていたら 4 章と 5 章の実通信を 1 回だけやり直す。それでも違えば、山名と違いを報告する。

7. **格子の確かめの残り**: 唐松岳(MSM・ECMWF)・妙高山・赤岳について、直す前の座標と直した後の座標で、応答の `latitude`・`longitude` が同じかを確かめる(点検と同じやり方。合計 12 回まで、タイムアウトは 3 回まで試す。コードは commit しない)。

## 6. 調べて報告するだけのこと(コードは変えない)
1. `msm_grid_elevation_m`: `precompute_terrain.py` が保存しているこの値が、本体のどこで読まれ、何の計算・表示に使われているか。使われていないなら「使われていない」。
   - 参考(作成者が Open-Meteo の説明ページで確かめたこと): 応答の `elevation` は、既定では問い合わせた地点の 90m の標高データの値で、気温などの補正(downscaling)に使われる。格子の平均の高さではない。また、格子の選び方(`cell_selection`)の既定 `land` は、問い合わせた地点と標高が近い陸の格子を選ぶ。
   - このため、座標が斜面の上にあると、格子の選び方や地上の気温の列に効くことがある。今回の 14 座で、地上の気温の列(`temperature_2m`)がどれだけ変わったかも、分かる範囲で書く。
2. バックテスト基盤への影響: 本体の座標が変わることで、`C:/yamabiyori-backtest`(古い本体 `C:/mountain-weather` を見ている)と何が食い違うかを、`docs/2.0-backtest-compat-notes.md` を読んでまとめる(触らない・変えない)。
