- 時間の見積もり = 足りない枚数 × 1 枚あたりの秒 + タイルのあとの予報と図づくりの秒。

## 7. 第 4 部: 同点の並び順

`git switch -c feature/ranking-clarity`(`feature/wait-notice` の先頭から)。

`mountain_weather_mvp.py` の日ごとの並び(今は `sorted(qualifying, key=lambda r: r["score"], reverse=True)`)を、次の順にする。

1. スコアの高い順(今までと同じ。スコアの値は変えない)。
2. 同点のとき: 危険信号の軽い順(なし → 注意 → 警戒 → 危険。山に 2 つ以上あるときは、いちばん重い段階で比べ、同じなら数の少ない順)。
3. それでも同じとき: 稜線風速の弱い順(値の無い行は最後)。
4. それでも同じとき: 山の ID の順。

- 「同点」は、今の表示の桁(小数 1 桁)で同じ値のこと。表示は同じなのに内部の小さな差で並びが決まる、ということが起きないようにする。
- 危険信号の段階は、行が今持っている値(`report_data.py` の `hazard_class()` などが使っているもの)から決める。新しい判定を作らない。
- 画面の表(`print_ranking_table`)・`--out` の文・`--json-out` の `rows[]` は、どれもこの並びになる。`--json-out` の `all[]` の並びは変えない。
- 画面の表の上に、同点が 2 座以上ある日は 1 行足す(例: `※ 98.6点が 71 座あります。同点の中は、危険信号の軽い順・稜線の風が弱い順に並べています。`)。この行が既存の回帰テストの期待値を変えるなら、2 章の例外には当たらないので、**標準エラーに出す**か、`--json-out` の項目(日ごとの `tie_note` など)だけにする。

テスト: 同点 3 座(危険・注意・なし)が「なし → 注意 → 危険」の順になる。危険信号が同じ 2 座が、風の弱い順になる。スコアの違う山の順は変わらない。`MOUNTAINS` の順番を入れ替えても、同点の並びが変わらない。

既存の見本・期待値で並びが変わるものは、2 章の例外の手順(ID で並べ直して、数字が同じことを確かめる)で直す。commit する。

## 8. 第 5 部: レポートの直し(`scripts/render_report.py`)

探索モードのレポート(`--data` と `--commentary`)を直す。

1. **おすすめの山を、日ごとのランキングにも必ず出す。** `commentary` の `picks`(と `avoid`)の山が上位(`--top`。既定 15)に入らない日は、その山の行を表の下に足す(区切りの行「おすすめの山(上位 15 座の外)」を入れる)。行には、その日の順位を出す。
2. **印を付ける。** ランキングの中のおすすめの山に「★」、避ける山に印(今の見た目に合うもの)を付け、表の下に凡例を 1 行出す。
3. **おすすめの表・避ける表に「順位」の列を足す。** 同点は同じ順位で、「1位(同点 71 座)」のように書く。
4. **同点の数を表の上に出す。** 同点が 2 座以上ある日は、ランキングの上に 1 行(7 章の例と同じ文)。
5. 今ある「76座中、75座が70点以上です。うち警戒以上の危険信号がある山は47座」の行は残す。

- `commentary` が無いとき・`picks` が無いときは、1〜3 は何もしない(今までどおり)。4 は出す。
- レポートの大きさが目立って増えないこと(変更前後のバイト数を控える)。
- スマートフォンの幅で表が崩れないこと(列を足すので、今の表の作り(横に送れる、など)に合わせる)。

テスト(`tests/test_report.py` に足す): おすすめの山が上位の外にある見本で、その山の行・印・順位が出る。`picks` の無い見本は、4 の 1 行のほかは変わらない。

commit する。

## 9. 第 6 部: ランキングを「行ける山」と「見送る山」に分ける(別の commit)

**この部は、利用者がまだ「分ける」と決めていません。** あとで外せるように、**これだけで 1 つの commit** にし、切り替えの引数を付けます。

- `scripts/render_report.py` に `--ranking-layout {split,single}` を足す。**既定は `split`**。`single` は第 5 部までの形(1 つの表)。
- `split`: 日ごとのランキングを 2 つの表にする。
  - 「行ける山」: 危険信号が警戒未満(なし・注意)の山を、7 章の並びで上位 `--top` 座。
  - 「見送る山(危険信号が警戒以上)」: 警戒・危険の山を、危険の重い順 → スコアの高い順 → ID の順で上位 `--skip-top` 座(既定 5。仮の値)。表の上に「スコアが高くても、危険信号が警戒以上の山です(危険信号はスコアとは別の警告)」と 1 行。
  - 「行ける山」が 0 座の日は、「この日は、危険信号が警戒未満の山がありません」と出す。
- 山域サマリー・おすすめの表・避ける表は変えない。
- 画面の表(`print_ranking_table`)は分けない(レポートだけ)。
- テストを足す(両方の引数で)。`skills/yamabiyori/references/report_style.md` と `README.md` に書く。

## 10. 第 7 部: おすすめを選ぶ手順書の直し

`skills/yamabiyori/references/recommend_guide.md`(と、要れば `report_style.md`)に足す。文書だけ。

1. 初心者・家族・デート向けのおすすめは、**危険信号なしの山を先に選ぶ**。注意つきの山を選ぶときは、理由を書く。警戒・危険の山はおすすめにしない。
2. **チャットの答えとレポートのおすすめを同じにする。** 両方を同じ `commentary`(`picks`・`avoid`)から作り、チャットの答えで挙げた山と、レポートの `picks` を一致させる。
3. **スコアが上位なのに外した山には、理由を書く**(`avoid` に入れる)。

### 11.2 報告書 `docs/wait-notice-ranking-report.md`

第 1〜3 部の分は `feature/wait-notice` に、第 4 部からの分は同じファイルへの追記として `feature/ranking-clarity` に commit する。
